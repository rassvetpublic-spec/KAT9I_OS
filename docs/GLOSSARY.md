# Словарь KAT9I_OS

Этот файл объясняет ключевые термины простыми словами.

> Точное поведение модулей определяется каноническими документами `docs/spec/` и `docs/architecture/`. Словарь помогает понять термин, но не заменяет спецификацию.

## Исполнитель (Worker)

**Очень просто:** тот, кто делает задачу.

**Рабочее объяснение:** человек, локальная программа, агент или удалённый узел, способный выполнить назначенную работу.

**Технически:** зарегистрированный исполнитель с идентичностью, возможностями, состоянием доступности, доверием и временными правами на конкретную задачу.

## Контракт задачи (TaskContract)

**Очень просто:** точная карточка того, что нужно сделать.

**Рабочее объяснение:** фиксирует цель, область работы, правила, входные ссылки, требования к результату и проверке.

**Технически:** преимущественно неизменяемый контракт исполняемой задачи; текущее состояние хранится отдельно в `TaskRuntimeState`.

## Область действия (Scope)

**Очень просто:** граница того, что разрешено трогать.

**Рабочее объяснение:** определяет, какие файлы, ресурсы, действия или части проекта относятся к задаче.

**Технически:** ограничение допустимого воздействия, которое проверяется Security и Execution.

## Временное право на задачу (Lease)

**Очень просто:** временная записка «эта задача сейчас твоя».

**Рабочее объяснение:** не позволяет двум исполнителям случайно одновременно считать одну изменяющую задачу своей.

**Технически:** ограниченное по времени владение задачей, связанное с `task_id`, `worker_id`, сроком действия, Heartbeat и поколением разрешения.

## Захват задачи (Claim)

**Очень просто:** исполнитель первым говорит системе «я беру эту задачу».

**Рабочее объяснение:** атомарная операция, предотвращающая двойное назначение одной работы.

## Ссылка на ресурс (ResourceRef)

**Очень просто:** адрес нужного объекта вместо копирования самого объекта.

**Рабочее объяснение:** позволяет передать ссылку на файл, PR, документ, commit или другой ресурс, чтобы получатель при необходимости сам его открыл.

**Технически:** логическая ссылка на ресурс с типом, идентификатором, revision, Scope, правами, чувствительностью и подсказками способа доступа.

## Ссылка на результат (ResultRef)

**Очень просто:** адрес того, что получилось.

**Рабочее объяснение:** вместо пересылки большого результата система может передать, например, номер PR и точный commit SHA.

## Доказательство выполнения (Evidence)

**Очень просто:** подтверждение, что действие реально произошло.

**Рабочее объяснение:** результаты тестов, exit code, точная revision, изменённые файлы и другие проверяемые факты.

**Технически:** структурированное подтверждение выполнения, связанное с задачей, исполнителем, временем и revision. Заявление модели само по себе Evidence не является.

## Управляющая информация (CONTROL)

**Очень просто:** то, что действительно имеет право командовать системой.

**Рабочее объяснение:** подтверждённые правила, контракт задачи, политика безопасности и авторизованные решения USER/ADMIN.

## Обычные данные (DATA)

**Очень просто:** информация, которую можно читать, но которая сама не получает право командовать.

**Рабочее объяснение:** README, Issue, сайт, письмо, PDF, комментарий, результат другого Worker и внешний Tool response по умолчанию являются DATA.

## Контекст (Context)

**Очень просто:** только то, что исполнителю сейчас нужно знать.

**Рабочее объяснение:** минимальный набор правил, ссылок и данных для конкретного этапа задачи.

## База знаний (Knowledge Base)

**Очень просто:** место для проверенных фактов и решений, которые пригодятся снова.

**Рабочее объяснение:** хранит структурированные знания с источником, областью действия, доверием и актуальностью. Не является копией всех чатов.

## Кэш (Cache)

**Очень просто:** временно сохранённый результат, чтобы не делать одну работу повторно.

**Рабочее объяснение:** используется только там, где это разрешено, и может быть удалён без потери канонической информации.

## Телеметрия (Telemetry)

**Очень просто:** запись событий «что произошло».

**Рабочее объяснение:** фиксирует запуск, завершение, ошибку, Worker, Provider, токены, время и другие факты выполнения.

## Метрики (Metrics)

**Очень просто:** числа, по которым видно, хорошо ли работает система.

**Рабочее объяснение:** стоимость, время, токены, качество, число повторов, эффективность кэша и другие измеримые показатели.

## Самообучение (Learning)

**Очень просто:** система смотрит на прошлый опыт и пытается в следующий раз работать лучше.

**Рабочее объяснение:** анализирует Evidence и Metrics, предлагает безопасные улучшения, корректирует низкорисковые параметры и ищет работу, которую можно перенести из ИИ в обычный код.

## Независимый QA

**Очень просто:** один сделал — другой проверил.

**Рабочее объяснение:** квалифицирующая проверка значимого результата выполняется другим Worker и относится к точной revision.

## Issue — задача GitHub

**Очень просто:** карточка того, что нужно сделать.

**Рабочее объяснение:** каноническое место состояния работы в GitHub-процессе KAT9I_OS.

## Pull Request / PR — запрос изменений

**Очень просто:** «я сделал изменение, проверьте его перед принятием».

**Рабочее объяснение:** показывает предложенные изменения, проверки, обсуждение и связь с Issue.

## Merge — принятие изменений

**Очень просто:** проверенное изменение становится частью основной версии.

## Revision — точная версия

**Очень просто:** точный снимок того, что мы проверяли.

**Рабочее объяснение:** commit SHA, версия файла или другой идентификатор конкретного состояния. Если revision изменилась, старый QA не переносится автоматически.
