# 37. SINGLE CONTROLLER ARCHITECTURE (FAN-OUT / FAN-IN)

## 1. Контекст и Проблема
Исторически для масштабирования задач использовался паттерн "4 независимых UI-окна (Workers)", которыми владелец управлял вручную. Это приводило к:
- **Распылению внимания (Context Switching):** Владелец терял фокус, пытаясь синхронизировать знания между окнами.
- **Потере идей:** "Супер-идеи" заставляли владельца плодить копии папок (например, `AGY1`, `AGY2`), нарушая версионирование и процесс QA.
- **Проблемам агрегации:** Было невозможно автоматически собрать разрозненные чаты в единый артефакт.

## 2. Решение: Единый Контроллер (The Orchestrator)
Архитектура переведена на паттерн **Fan-Out / Fan-In**, где существует только **один** пользовательский интерфейс (Controller).

### 2.1. Распределение задач (Fan-Out)
При поступлении сложной задачи (команда `/boost` или `/teamwork-preview`), Единый Контроллер переходит в `Delegation Routine`. Он не решает задачу сам, а динамически запускает N невидимых фоновых сабагентов (`invoke_subagent`):
- **DeepCoder** — для написания и исправления кода.
- **DeepInvestigator** — для сложных исследований, дебага и анализа логов.

### 2.2. Сбор результатов (Fan-In)
Фоновые сабагенты работают в том же Workspace (или в изолированных `git worktree`), не требуя собственных окон интерфейса. По завершении они возвращают результаты по внутренней шине сообщений обратно Контроллеру. Контроллер валидирует их работу (QA) и формирует финальный ответ владельцу.

## 3. Интеграция с CKS (Context Knowledge System)
Синхронизация знаний между сабагентами больше не требует ручного экспорта логов чата.
- **Дистилляты:** Каждый сабагент в конце своей работы формирует JSON-объект `distillate_object_v1`.
- **Проксирование:** KAT9I_OS перехватывает эти дистилляты и помещает их в очередь.
- **Сохранение:** Фоновый процесс `TRIM` верифицирует знания и сохраняет их в базу `CKS`, делая доступными для всех будущих сессий.

## 4. Управление Вниманием и "Супер-Идеями"
Контроллер аппаратно защищает владельца от расфокусировки через **Протокол Жесткого Прерывания (Hard Interruption)** (см. `AGENTS.md`):
1. Контроллер отказывается писать код вне Scope.
2. Проводит `ABC/XYZ анализ` приоритетов.
3. Сохраняет идею как Issue (Идейный Склад).
4. Если эксперимент неизбежен, Контроллер автоматически создает изолированный `git worktree` (ветка `spike/`).

## 5. Статус легаси
Скрипты `ArrangeWindows.ps1`, `WorkerUIOverlay.ps1` и ручной запуск 4-х профилей (`DirectLaunch.ps1`) официально признаны **Deprecated** и перенесены в Graveyard.
