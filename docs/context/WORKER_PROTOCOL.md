# WORKER Protocol

## Назначение

Короткий операционный контракт Implementation Worker. Канонические ограничения см. также в `AGENTS.md`, `QA_PROTOCOL.md` и `docs/spec/24_GITHUB_PROJECT_MANAGEMENT.md`.

## Взятие задачи

Worker:

- берёт только разрешённую QUEUE-GUARD задачу;
- читает Issue/PR и зависимости до изменений;
- оставляет `FAST-CLAIM` / заметку «взял в работу»;
- работает только в Scope своего ChangeSet;
- поддерживает Project-карточку как производное представление SSoT.

## Эксклюзивное владение

Один активный ChangeSet имеет одного Implementation Worker. Пока claim активен:

- другой Worker не меняет рабочую ветку;
- не создаёт дубль PR/Issue на тот же ChangeSet;
- может анализировать и оставлять рекомендации без mutation;
- непересекающаяся speculative preparation допустима, но не даёт права обогнать queue head.

## Автоматический режим

Worker выполняет безопасные обратимые шаги автоматически и не зовёт владельца для рутинных подтверждений.

Остановка и вопрос владельцу обязательны при:

- нехватке доступа;
- конфликте канонических правил;
- необходимости изменить Scope/Gate;
- риске необратимой потери данных;
- необходимости `mtd` для merge.

## Перед QA

До handoff:

- детерминированные проверки должны быть выполнены;
- blocking review findings должны быть устранены или явно классифицированы;
- exact HEAD фиксируется;
- Worker не объявляет собственный квалифицирующий QA PASS.

После handoff frozen revision Worker не меняет branch до завершения/инвалидации QA-сессии. Детали freshness и 40-секундного quiet window задаёт `QA_PROTOCOL.md`.

## Завершение

Worker передаёт Evidence Controller. После разрешённого merge выполняется read-back Issue/PR/Project и, если предусмотрено процессом, `FAST-RELEASE`.

Merge без отдельного свежего `mtd` запрещён.
