# Карта соответствия GitHub ↔ KAT9I_OS

## 1. Назначение

Настоящий документ устанавливает однозначное понятийное и операционное соответствие между механизмами совместной разработки GitHub и внутренними архитектурными сущностями KAT9I_OS.

> **Главный принцип:**
> Карта объясняет соответствие сущностей для коворкеров и автоматических агентов, но **не создаёт параллельных источников истины** и новых сущностей внутри KAT9I_OS.

---

## 2. Сводная таблица соответствия сущностей

| Сущность GitHub | Роль в GitHub | Соответствующая сущность KAT9I_OS | Статус источника истины | Описание взаимодействия |
|---|---|---|---|---|
| **`docs/` (Markdown)** | Хранилище документации | **Каноническая архитектура и спецификации** | **ДА** (для архитектуры и правил) | Единственный первоисточник проектных решений, контрактов и ТЗ. |
| **Issue (задача)** | Карточка задачи, баг-репорт или запрос фичи | **TaskContract / Рабочая задача** | **ДА** (для состояния работы) | Фиксирует цель, границы (Scope), контекст и текущий статус исполнения. |
| **Branch (ветка)** | Изолированная линия изменений | **Изолированный Workspace Worker** | Нет | Рабочее пространство исполнителя для внесения правок до сдачи результата. |
| **Commit** | Сохранённая фиксация файлов | **Шаг исполнения / Инкремент состояния** | Нет | Атомарный зафиксированный шаг работы с указанием автора, времени и diff. |
| **Pull Request (PR)** | Запрос на слияние изменений | **Предложение изменения / ResultRef** | Только для предложенного изменения | Оформленное предложение результата работы Worker со ссылкой на решённую задачу (Issue). |
| **GitHub Actions** | Автоматизированный CI/CD пайплайн | **Automated Evidence / CI Gates** | **ДА** (для факта проверки точной revision) | Машиночитаемые доказательства прохождения тестов, линтеров и проверок целостности. |
| **QA Approval / Review** | Подтверждение от рецензента | **Независимый QA (Independent QA)** | **ДА** (для валидации точной revision) | Подтверждение качества другим Worker (`Implementation Worker != QA Worker`). |
| **Merge** | Включение изменений в основную ветку | **Result Integration / Task Completion** | Нет | Фиксация проверенного результата в каноническую ветку `main` и закрытие задачи. |
| **Project (доска)** | Канбан-доска со столбцами статусов | **Визуализация состояния задач** | **НЕТ** (только производное представление) | Наглядное отображение движения Issues без создания отдельного состояния. |
| **Milestone (этап)** | Группировка задач к релизу | **Этап дорожной карты (Roadmap Phase)** | **НЕТ** (только группировка) | Пакет задач для конкретной версии (например, `v0.1`, `v0.2`, `v1.0`). |
| **Release** | Официальная публикация релиза | **Релизный артефакт / Milestone Sealed State** | **ДА** (для факта официального выпуска) | Зафиксированная версия с неизменяемыми тегами, хэшами и списком изменений. |
| **Discussions** | Форум для вопросов и идей | **Неструктурированный контекст / Идеи** | **НЕТ** | Место для обсуждений, обучения и вопросов. Решения переносятся в `docs/` или Issues. |
| **GitHub Pages** | Публикация веб-сайта | **Визуальная витрина документации (HTML View)** | **НЕТ** (только производное представление) | Сгенерированное HTML-представление из `docs/` с интерактивными фильтрами и режимами. |
| **CODEOWNERS** | Автоматический запрос review | **Маршрутизатор проверок (Review Router)** | **НЕТ** | Сервисный механизм GitHub для назначения ревьюеров; не подменяет архитектурную карту ролей. |

## 3. Операционный цикл задачи (Lifecycle Mapping)

Стандартный цикл прохождения задачи в KAT9I_OS через GitHub выражается однозначной цепочкой:

```
[Идея / Вопрос] (Discussions / Обратная связь)
       ↓
[Задача] (GitHub Issue = TaskContract)
       ↓
[Ветка] (Git Branch = Изолированный Workspace)
       ↓
[Фиксация] (Git Commit = Шаги выполнения)
       ↓
[Запрос изменений] (GitHub PR = Предложение результата и ResultRef)
       ↓
[Проверки роботами] (GitHub Actions = Automated Evidence)
       ↓
[Проверка человеком/аудитором] (QA Worker Approval = Independent QA)
       ↓
[Принятие изменений] (PR Merge = Интеграция в main и закрытие Issue)
       ↓
[Официальный выпуск] (GitHub Release = Зафиксированная версия системы)
```

---

## 4. Памятка для коворкеров и агентов

1. **Не создавайте второй источник истины:**
   - Если утверждение сделано в Issue или PR, но не внесено в `docs/`, оно не является канонической архитектурой KAT9I_OS.
2. **Не путайте представление и данные:**
   - Изменение положения карточки на доске Project не меняет суть задачи, пока не обновлён статус самого Issue.
   - Ошибка публикации Pages — это ошибка представления, а не архитектурный отказ системы.
3. **Разделяйте роли исполнителя и проверяющего:**
   - Тот Worker, который создал PR, не может сам себе подписать независимый QA.
