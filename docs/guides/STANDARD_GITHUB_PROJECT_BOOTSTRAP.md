# Стандартная подготовка GitHub-проекта

Статус: рабочий стандарт v1, Issue #181.

## Назначение

Одна точка входа приводит новый или существующий GitHub-проект к нашему базовому рабочему стандарту без повторной ручной настройки через интерфейс GitHub.

Подготовка охватывает:

- настройки репозитория;
- русские метки;
- русские формы задач;
- русский шаблон запроса на слияние;
- CODEOWNERS;
- правила для ИИ-исполнителей;
- базовую автоматическую проверку качества;
- GitHub Project V2;
- поля доски проекта;
- итерацию длительностью 3 дня;
- восемь русских представлений доски;
- добавление открытых задач и запросов на слияние на доску;
- защиту ветки `main`;
- обязательную проверку качества;
- проверку наличия необходимых возможностей и имён секретов без чтения их значений;
- итоговую машиночитаемую квитанцию.

## Режимы

### Установка

Создаёт отсутствующие стандартные элементы и безопасно приводит известные настройки к стандарту.

### Статус

Только читает состояние GitHub. Ничего не создаёт, не изменяет и не удаляет.

### Восстановление

Исправляет только те элементы, которые однозначно принадлежат стандартной подготовке. Неизвестные пользовательские файлы и потенциально разрушительные расхождения не перезаписываются автоматически.

## Доска проекта

Стандарт создаёт или подключает GitHub Project V2 и поддерживает восемь представлений:

1. `00 — Обзор`;
2. `01 — Очередь`;
3. `02 — Активная работа`;
4. `03 — Проверка качества`;
5. `04 — Подготовка выпуска`;
6. `05 — План развития`;
7. `06 — Заблокировано / Парковка`;
8. `07 — Показатели исполнителей`.

Задачи и запросы на слияние остаются источником истины работы. Доска проекта является производным представлением и не создаёт второй жизненный цикл задач.

## Безопасность

- команда владельца `mtd` никогда не автоматизируется;
- автоматическое слияние не включается;
- значения секретов не читаются и не попадают в журнал или квитанцию;
- неизвестные пользовательские метки сохраняются;
- неизвестные пользовательские файлы не перезаписываются;
- неизвестные представления доски блокируют потенциально разрушительное автоматическое восстановление;
- существующие идентификаторы вариантов полей доски не заменяются, если в проекте уже есть карточки;
- защита `main` проверяется повторным чтением после применения.

## Совместимость

Английские названия старых полей и представлений могут встречаться только внутри миграционных алиасов. Новая пользовательская конфигурация создаётся на русском языке.

`AGY`, `mtd`, имена GitHub API, имена файлов и идентификаторы машинных схем являются техническими идентификаторами и не переводятся, если перевод нарушил бы совместимость.

## Граница ответственности

Этот стандарт автоматизирует подготовку GitHub и доски проекта. Он не заменяет прикладные тесты конкретного репозитория и не выдаёт себе полномочия независимой проверки или слияния.

Исполнитель изменений: ChatGPT.
Независимый проверяющий: Антигравити.
Финальное слияние: только после отдельной команды владельца `mtd`.
