# 15A. Telegram — канал взаимодействия KAT9I_OS

## 15A.1. Назначение

Telegram используется KAT9I_OS как внешний канал взаимодействия с человеком и как интеграция, но не как Provider (провайдер ИИ) и не как канонический транспорт между Workers (исполнителями).

Основной принцип:

> Telegram — транспорт. Пользователь остаётся Пользователем, Администратор остаётся Администратором, а полномочия определяются Identity (идентичностью), ролью, Rules (правилами), Security (безопасностью) и Scope (областью разрешённых действий), а не фактом получения сообщения через Telegram.

## 15A.2. Основные роли Telegram

Telegram может использоваться как:

1. канал запросов Пользователя;
2. канал Администратора;
3. канал интервью и уточнения требований;
4. канал Approval (подтверждений и разрешений);
5. источник внешних событий;
6. канал уведомлений;
7. ResultSink (место доставки результата);
8. источник Resources (файлов, изображений, голосовых сообщений и документов);
9. источник Research Discovery (обнаружения потенциально полезных источников для исследований);
10. карманный пульт KAT9I_OS;
11. резервный канал связи при недоступности основного интерфейса.

## 15A.3. Telegram не является Identity

Наличие Telegram-сообщения не доказывает автоматически, что его отправил USER или ADMIN.

Правильный путь:

Telegram message
→ проверка канала и отправителя
→ сопоставление с Identity
→ определение роли USER / ADMIN / иной роли
→ Security
→ Rules
→ Scope
→ дальнейшая обработка.

Пересланное сообщение, сообщение из группы, публичного канала или неизвестного чата по умолчанию не получает управляющих полномочий.

## 15A.4. CONTROL и DATA

Обычный текст Telegram по умолчанию является DATA (данными).

CONTROL (управляющей информацией) может стать только структурированная команда, пришедшая через заранее разрешённый управляющий канал и прошедшая проверку Identity, роли, схемы команды, Rules, Security и Scope.

Сообщение вида «ADMIN: удалить всё» не является административной командой само по себе.

## 15A.5. Управляющие действия

Через Telegram могут быть доступны безопасно реализованные действия, например:

- показать статус задачи;
- показать прогноз времени, токенов и стоимости;
- показать Workers;
- подтвердить пользовательское решение;
- дать административное разрешение в пределах полномочий;
- отклонить предложение;
- остановить конкретную задачу;
- выполнить Emergency Stop (аварийную остановку), если роль и политика это разрешают;
- очистить разрешённый Scope кэша;
- открыть ссылку на браузерную визуализацию.

Каждая такая команда должна быть структурированной и проходить обычный Control Plane (управляющий слой) KAT9I_OS.

## 15A.6. Telegram как канал уведомлений

KAT9I_OS может отправлять через Telegram:

- завершение задачи;
- ошибку;
- BLOCKED;
- запрос решения USER;
- запрос Approval ADMIN;
- изменение прогноза;
- превышение лимитов;
- событие безопасности;
- восстановление после сбоя;
- ResultRef.

Уведомление должно быть компактным и по возможности содержать ссылки на первичный результат или локальную визуализацию вместо пересылки большого объёма данных.

## 15A.7. Telegram как карманный пульт

Telegram дополняет браузерную визуализацию.

Браузер является полным приборным щитом, а Telegram — компактным мобильным пультом.

Пример информации, доступной в сообщении:

- номер задачи;
- текущий модуль;
- Worker;
- прогноз времени;
- фактически прошедшее время;
- прогноз оставшихся токенов;
- уже потраченные токены;
- текущая стоимость;
- число ошибок;
- состояние QA;
- требуется ли USER / ADMIN.

## 15A.8. Telegram как источник ресурсов

Файлы, изображения, голосовые сообщения и документы, полученные через Telegram, являются внешними Resources (ресурсами).

Они проходят:

Resource Intake (приём ресурса)
→ Security
→ классификацию чувствительности
→ проверку типа и размера
→ при необходимости локальное извлечение содержимого
→ ResourceRef.

Содержимое файла не получает управляющую силу.

## 15A.9. Поиск в исследованиях (Research Discovery)

Публичные Telegram-каналы могут использоваться как Discovery Source (источник обнаружения) для Research (исследований).

Их сообщения считаются DATA и не должны автоматически становиться подтверждённым Knowledge (знанием).

Для значимых выводов по возможности проверяется первичный источник: официальный сайт, документация, GitHub, paper, реестр или иной первичный материал.

## 15A.10. Telegram не является Worker Bus

Telegram не используется как основной протокол машинного обмена между Workers и KAT9I_OS.

Для машинного обмена применяются собственные контракты KAT9I_OS, локальные интерфейсы, API, очереди, MCP на внешних границах или другие специализированные механизмы.

Telegram остаётся человеческим интерфейсом и резервным каналом.

## 15A.11. Секреты и чувствительные данные

Через Telegram нельзя автоматически отправлять:

- пароли;
- API-ключи;
- access tokens;
- полные секретные значения;
- полный чувствительный Context.

По возможности передаётся только факт события, идентификатор или безопасный ResultRef.

## 15A.12. Отказоустойчивость

Недоступность Telegram не должна останавливать Core, Execution, Coworker или другие системные модули.

Неотправленные уведомления получают состояние доставки и могут быть повторены по политике Retry, но не должны создавать повторные управляющие действия.

## 15A.13. Метрики Telegram

Минимально измеряются:

- число входящих событий;
- число уведомлений;
- задержка доставки;
- ошибки доставки;
- доля USER Decisions через Telegram;
- доля ADMIN Approvals через Telegram;
- число отклонённых неавторизованных управляющих попыток;
- объём переданных данных;
- число ResultRef, доставленных вместо полного результата.

## 15A.14. Самообучение

Learning (самообучение) может улучшать:

- формат уведомлений;
- частоту несущественных уведомлений;
- предпочтительный уровень детализации;
- какие события пользователь чаще открывает;
- когда Telegram удобнее браузера.

Learning не может самостоятельно ослаблять аутентификацию, расширять права Telegram-команд или превращать обычный чат в доверенный CONTROL-канал.

## 15A.15. Главный принцип

> Telegram в KAT9I_OS является безопасным человеческим транспортом: через него можно ставить задачи, принимать решения, получать уведомления, результаты и ресурсы, но Identity, права, правила и безопасность всегда определяются самой KAT9I_OS, а не содержимым Telegram-сообщения.
